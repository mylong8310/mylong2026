# 动衡 FitBalance · App Design Taste v0.1 实验记录

- 日期：2026-11-05
- 原始业务分支：`fitbalance-apk-20261006`（v1.6.0 RC）
- 独立实验分支：`experiment/fitbalance-taste-v01`
- 来源：用户提供的跑步 App 前后对比图；按 `app-design-taste` Beta Skill 的禁止项 / 设计系统 / 风格方向 / 交付自检进行审查。
- 不将跑步 App 的数值、行业文案、配色完整移植到 FitBalance。
- **原有 JS / Android / 数据库 / 业务逻辑未修改。** API 仍保持原版策略。

## A / B

**A 现有版**：沿用 `app.css`，不新增覆盖层。

**B 试验版**：在 `app.css` 之后加载 `app-taste.css`，使用“石墨黑 / 植物浅绿 / 低饱和状态色”的动衡专属方向。

独立修改：
- 首页主 KPI“净摄入 kcal”：突出真实数据、数值对齐，正文次级；
- 关键次级数据“摄入 / 活动消耗 / 步数”：改变大小和背景层级，不伪造曲线；
- 宏量营养 / 16:8：克制背景、细进度条、间距和字号统一；
- 导航：去 Emoji，改为同一套描边图标、真实 HTML button（键盘可操作）；
- 紧急联系：保留红色危险语义和按钮，不用视觉极简掩盖；
- 小屏 / 减少动态效果 / 焦点态：显式处理。

## 使用前检查

1. **差分范围**：确认仅 `index.html` 和新建的 `app-taste.css` 发生 UI 改动。
2. **5 个页面**：首页、饮食、运动、身心、我的；点击导航可切换，返回首页成功。
3. **核心动态 ID**：`balanceKcal`, `homeIntake`, `homeBurn`, `homeSteps`, `proteinBar`, `carbBar` 未改。
4. **计量**：kcal、步数、克数不因样式变化而改变单位/数值。
5. **危险入口**：紧急呼叫和高风险健康提示未隐藏，仍需验证调用。
6. **状态**：首次启动 onboarding、无数据、无传感器、数据较大、断网场景。
7. **屏宽**：360、390、430px 等安卓视口，系统字体增大和安全区。
8. **对比/可达性**：暗底标签可读；触控尺寸 >= 44px；焦点可见。
9. **发行安全**：禁止未经完整 Android 构建/签名校验即发布正式 APK。
10. **验收**：依据四类评分标准（视觉、内容、可用性、技术）复评，而非只凭首屏效果图。
